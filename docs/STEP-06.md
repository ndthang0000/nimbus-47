# Step 6: Docker and a Daily DigitalOcean Job

Status: Docker verified locally; manual DigitalOcean run verified; daily cron installed and active. Scheduled invocation verified: October 13, 2026 at 19:00:01 UTC (October 14 at 02:00:01 Vietnam), exit 0. Published evidence is linked in README.md.

## 1. Local Docker Verification (PowerShell)

```powershell
docker build -t nimbus-47:latest .
docker run --rm --env-file .env nimbus-47:latest --check-config
docker run --rm --user 0:0 --env-file .env -e STATE_DIR=/state -e DATA_DIR=/data/articles --mount "type=bind,src=$($PWD.Path)\state,dst=/state" --mount "type=bind,src=$($PWD.Path)\data,dst=/data" nimbus-47:latest
```

The default command runs `main.py --sync` once. Successful runs exit zero. The environment file is supplied at runtime and excluded from the build context. The image includes a cached tokenizer so retrieval preparation does not need to download it during each run.
The Windows bind-mount command uses container root to accommodate Docker Desktop permissions on existing files. The Linux host runner uses the deployment account's UID/GID instead. The image defaults to a non-root user.

## 2. Provision a Droplet

Create an Ubuntu LTS Droplet with SSH-key access and an appropriately sized plan (check the price in the creation screen). Singapore is a suitable nearby region. This creates a billable resource. Configure SSH access for your deployment account and install Docker, Git, Python 3 and util-linux (`flock`). Restrict inbound access to SSH; this background job does not require HTTP ports.

Docker installation: https://docs.docker.com/engine/install/ubuntu/
Droplet setup: https://docs.digitalocean.com/products/droplets/getting-started/recommended-droplet-setup/

The deployment account must be able to run Docker. Docker access grants substantial host privileges; use a dedicated account.

## 3. Prepare Host Directories

As an administrator, create `/opt/nimbus-47` owned by the deployment account. As that account:

```bash
mkdir -p /opt/nimbus-47/{state,data,logs,secrets,artifacts}
chmod 700 /opt/nimbus-47/secrets /opt/nimbus-47/state
git clone git@github.com:ndthang0000/nimbus-47.git /opt/nimbus-47/app
cd /opt/nimbus-47/app
docker build -t nimbus-47:latest .
```

For a public repo, HTTPS clone is also suitable. A private repo requires authorized GitHub access; do not copy your personal private SSH key onto the server.

Create `/opt/nimbus-47/secrets/runtime.env` using an editor and set permissions to 600. Use the values in `.env.sample`, including `API_KEY`, `AI_PROVIDER=openai` and `ARTICLE_LIMIT=50`. Do not put secrets in shell command arguments or Git. The runner overrides data/state paths to mounted directories.

## 4. Transfer Existing State

Before the first cloud run, stop local sync activity and copy the current `state/openai.json` over SSH to `/opt/nimbus-47/state/openai.json`. Keep the API key and state associated with the same OpenAI project. Protect the destination file; it contains operational metadata, not the API key.

This preserves the existing vector store and prevents a full initial upload. Data can be regenerated by the scraper. Missing state creates a new store. If the existing store has expired, inspect it and deliberately establish a replacement rather than repeatedly retrying a stale ID.

## 5. Run on the Host

```bash
/bin/bash /opt/nimbus-47/app/deploy/run-sync.sh
echo $?
cat /opt/nimbus-47/artifacts/latest-run.json
```

Run twice. If source content is unchanged, each run should skip 50 articles and upload zero chunks. Check the original store ID remains in the manifest. The runner mounts host state/data, locks the entire operation, captures stdout/stderr and preserves the container exit code.

Host layout:

```text
/opt/nimbus-47/app/                    source and Dockerfile
/opt/nimbus-47/state/openai.json      durable sync state
/opt/nimbus-47/state/sync-report.json latest successful sync report
/opt/nimbus-47/data/articles/         regenerated Markdown
/opt/nimbus-47/logs/<run-id>.log       detailed execution log
/opt/nimbus-47/artifacts/             safe run summaries
/opt/nimbus-47/secrets/runtime.env    runtime credentials
```

Host disk survives container replacement, but not Droplet deletion. Back up state privately. Failed runs generate a failure artifact without falsely reusing previous successful counts. The successful sync report remains unchanged after a failure.

## 6. Schedule Once a Day

Check `timedatectl`; set the host timezone to UTC if necessary. Edit the deployment user's crontab with `crontab -e` and add the contents of `deploy/daily.cron.example`. Ensure the cron service is enabled after reboot.

The schedule runs at 19:00 UTC daily, corresponding to 02:00 Vietnam time the next day. Verify with `crontab -l` and inspect the next actual scheduled execution. `flock` skips overlapping runs with exit code 75. Logs are retained for 14 days; summaries are preserved.
